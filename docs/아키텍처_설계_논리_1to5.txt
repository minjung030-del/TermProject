민정님이 구상하신 시스템의 목적과 하드웨어 제약 조건을 고려하면, 비선점형 협력형 슈퍼루프(Cooperative Super-Loop)가 선점형(Preemptive RTOS)보다 시스템 설계 의도에 훨씬 더 부합하는 최적의 아키텍처입니다.

단순히 "구현이 쉬워서"가 아니라, 하드웨어 스펙과 연산 주기를 계산했을 때 협력형 모델이 선택되어야만 하는 4가지 공학적 이유가 있습니다.


1. 하드웨어 FIFO 버퍼 여유와 렌더링 시간의 조화 (가장 결정적인 이유)

선점형 OS가 반드시 필요한 상황은 "무거운 작업(FFT/VGA)을 하느라 CPU가 몇십~몇백 ms 동안 묶여서, 그사이에 작은 I/O 버퍼가 넘쳐버릴 때"입니다. 하지만 이 시스템은 그렇지 않습니다.

o   오디오 FIFO의 버퍼 수용 한계:
    o   샘플 레이트가 8 kHz 일 때, 1개 샘플이 소비되는 시간은 125 μs입니다.
    o   DE1-SoC Audio Core의 HW FIFO 용량은 128 샘플입니다. 즉, CPU가 FIFO를 전혀 건드리지 않아도 최대 16 ms (128 × 125 μs) 동안 오버플로우 없이 버팁니다.

o   33ms 분기( render_frame )의 실제 소요 시간:
    o   16비트 고정소수점 64-point FFT 연산: 50 MHz Nios II 기준 약 0.5 ms 미만.
    o   선택적 소거(Selective Erase) 기반 VGA 픽셀 드로잉: 약 1.5 ~ 2 ms 내외.
    o   즉, 33ms 주기 렌더링에 진입해서 빠져나오는 데 걸리는 총시간은 길어야 2 ~ 3 ms에 불과합니다.

렌더링 파이프라인이 2 ms 만에 끝나고 즉시 메인 루프로 돌아오므로, 16 ms의 버퍼 여유를 가진 오디오 FIFO는 선점형 스케줄러로 중간에 강제로 뺏지 않아도 절대 넘치지 않습니다.


2. 동기화 객체(Mutex, Semaphore) 및 크리티컬 섹션 오버헤드 배제

계측기 시스템은 화면 버퍼(VGA On-chip RAM)와 스펙트럼 배열( fft_real[] ), 좌표 변수( g_scope , g_mouse ) 등 대규모 공유 데이터를 다룹니다.

o   선점형일 경우:
    o   Task 3(VGA 드로잉)이 화면에 파형 픽셀을 찍는 도중 1ms 타이머 인터럽트로 Task 2(마우스)나 Task 1(오디오)이 선점해 버리면, 변수 상태가 꼬여 화면에 깨진 파형(Tearing)이 나타나거나 레이스 컨디션(Race Condition)이 발생합니다.
    o   이를 막기 위해 인터럽트를 끄거나( cli / sti ) Mutex를 걸어야 하는데, 이는 50 MHz의 소형 CPU에 막대한 사이클 낭비를 초래합니다.

o   협력형 슈퍼루프일 경우:
    o   한 번 호출된 함수는 자신이 끝날 때까지 CPU를 독점(Run-to-Completion)하므로, 모든 공유 메모리 접근이 별도의 락(Lock) 없이도 100% 원자성(Atomicity)을 보장받습니다.


3. 온칩 메모리(On-chip SRAM) 및 클록 사이클 보존

Nios II 임베디드 시스템은 가용 온칩 RAM(수십~256 KB)과 코어 클록(50 MHz)이 매우 한정적입니다.

o   스택 메모리 절약:
    o   선점형 RTOS는 태스크마다 최소 1~2 KB의 독립 스택을 별도로 할당해야 하므로 메모리 낭비가 큽니다.
    o   협력형은 단 하나의 시스템 호출 스택(Single Stack)만 공유하므로 메모리 풋프린트가 극단적으로 작습니다.

o   컨텍스트 스위칭 비용 제로:
    o   Nios II는 범용 레지스터가 32개나 됩니다. 선점형 스위칭이 1ms마다 일어난다면 매초 수천 번씩 30여 개의 레지스터를 메모리에 넣고 빼느라 실제 연산(DSP)에 쓸 클록 사이클을 허비하게 됩니다.
    o   협력형은 일반 C 함수 호출/복귀( call / ret ) 메커니즘만 사용하므로 CPU 오버헤드가 사실상 0에 가깝습니다.


4. 엄격한 결정론적 실행(Deterministic Timing) 보장

계측기(DSO)에서 가장 중요한 품질은 화면 깜빡임 없는 일정한 프레임레이트(Jitter 없는 30 FPS)와 입력 지연(Latency)의 최소화입니다.

o   선점형에서는 우선순위 역전(Priority Inversion)이나 스케줄러 틱 지연으로 인해 프레임 주기가 31ms, 36ms 등으로 불규칙하게 흔들리는 지터(Jitter)가 발생하기 쉽습니다.

o   협력형 슈퍼루프는 "초고속 I/O 루프 순환 -> 정확히 33ms 도달 시 DSP/VGA 일괄 처리 후 복귀"라는 단일 시퀀스를 엄격히 지키므로, 실행 시간의 불확실성이 전혀 없는 하드 실시간(Hard Real-Time) 특성을 가집니다.


보고서 및 발표용 한 줄 논리

"오디오 FIFO(16ms 허용치) 대비 렌더링 파이프라인의 WCET(최악 실행 시간, 약 2ms)가 현저히 짧아 태스크 기아(Starvation)가 발생하지 않으므로, 불필요한 컨텍스트 스위칭 오버헤드와 동기화 락(Lock)을 배제하고 결정론적 30 FPS를 보장하는 '협력형 슈퍼루프 아키텍처'가 가장 최적화된 설계이다."
